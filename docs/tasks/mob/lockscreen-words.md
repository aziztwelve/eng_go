# Lock Screen Words — слова на экране блокировки

**Статус:** 📝 Planning
**Сложность:** Средняя
**Затрагивает:** `eng_mob` (backend — 0 изменений в MVP; серверная опция — Future)
**Зависимости:** Phase 3 (push infrastructure, `expo-notifications`), Phase 7
(word flashcards, `FlashcardsApi`), онбординг (`proficiency_level` из
`useOnboardingState`).

---

## 1. Цель

Пользователь периодически видит английское слово с переводом прямо на
экране блокировки — без открытия приложения. Каждый раз, глядя на телефон,
он пассивно повторяет лексику. Частота настраивается: каждые 10 / 20 / 30 /
60 / 120 минут. Ночью уведомления не приходят («тихие часы»).

Источник слов — то, что юзер реально учит: сначала его flashcards-библиотека,
при нехватке — добор словами его уровня из общего словаря. В уведомлении
сразу видны слово + перевод: одно касание взглядом, тап открывает библиотеку.

## 2. Почему уведомления, а не виджет

Lock-screen виджеты недоступны сторонним приложениям на современном Android
(Google открыл их в Android 16 только для ограниченного набора приложений).
Рабочий паттерн для «word of the day»-приложений — **периодические локальные
уведомления**: они видны на экране блокировки, не требуют открытого
приложения и поддерживаются `expo-notifications` из коробки.

Осознанные компромиссы:

- **Doze / экономия батареи.** После долгого простоя система может
  сгруппировать несколько уведомлений и показать их вместе при следующем
  пробуждении устройства. Для нашей механики это допустимо (взял телефон →
  стек свежих слов) и даже удобно.
- **Без exact-alarms.** Не запрашиваем `SCHEDULE_EXACT_ALARM` / не используем
  `USE_EXACT_ALARM`: это отдельное чувствительное разрешение с Play-политикой.
  Обычные интервальные триггеры достаточны.

## 3. Архитектура (MVP — только mobile)

```text
FlashcardsApi.list({archived:false})        VocabularyApi.list({level})
        │  (word + translation)                     │
        └──────────────┬─────────────────────────────┘
                       ▼
              getWordPool()  ← shuffle + курсор (AsyncStorage)
                       │
                       ▼
              reschedule()
                       │  отменяет прошлые id,
                       │  строит ≤64 слотов на ~24ч вперёд,
                       │  слоты в тихие часы → сдвиг на утро
                       ▼
   scheduleNotificationAsync × N   (каждое — своё слово)
                       │
                       ▼
   канал "lockscreen-words" (silent, VISIBILITY_PUBLIC)
                       │
        ┌──────────────┴────────────────┐
        ▼                               ▼
  lock screen: слово + перевод    тап → deep link /practice/library
```

Ключевые решения:

- **Пул слов на клиенте.** Shuffle при каждом `reschedule()`, курсор в
  AsyncStorage — слова не повторяются, пока пул не пройден целиком.
  Полный цикл офлайн-совместим: работают ранее запланированные уведомления.
- **Планирование партией, не одно повторяющееся.** Каждое уведомление несёт
  своё слово, поэтому планируем до 64 будущих слотов (24ч при 30-мин
  интервале; при 10-мин — ~10ч запаса, `reschedule()` на каждом foreground
  пополняет). `Notifications.cancelScheduledNotificationAsync` по
  сохранённым id перед перепланированием.
- **Тихие часы.** Дефолт 22:00–08:00. Слоты, попавшие в окно, сдвигаются на
  утро того же цикла.
- **Отдельный канал Android** (`lockscreen-words`): без звука (слово читают,
  а не слушают), `VISIBILITY_PUBLIC` — текст виден на lock screen при любых
  системных настройках отображения.
- **Ответ на тап.** В `setupPushHandler()` (push-registration.ts) сейчас нет
  `addNotificationResponseReceivedListener` вообще — добавляем его:
  response на канал lockscreen-words → `router.push('/practice/library')`.
- **Refresh на foreground.** `AppState` listener в `_layout.tsx`: каждый
  возврат в приложение → `reschedule()` — свежие слова, пополнение очереди,
  актуальный конфиг.

## 5. Тест-план

Статика:

```bash
npx tsc --noEmit   # clean
npm run lint       # clean
```

Ручной чек-лист на физическом устройстве (Metro):

1. Включить фичу → разрешение «Уведомления» запрошено → заблокировать
   телефон → слово появилось на lock screen в течение интервала.
2. Тап по уведомлению → открыт `/practice/library`.
3. Тихие часы: выставить окно, накрывающее текущее время → уведомления не
   приходят; после окончания окна — приходят.
4. Смена интервала 30 → 10 мин → следующее уведомление по новому интервалу.
5. Выключение фичи → все запланированные уведомления отменены.
6. Повторное включение → расписание восстановлено.
7. Doze (опционально): `adb shell dumpsys deviceidle` → после пробуждения
   сгруппированные уведомления показываются, без крашей.

## 6. Ограничения платформы

- **Android 13+**: `POST_NOTIFICATIONS` — runtime permission; при отказе
  фича не включается, экран показывает статус и кнопку в системные настройки.
- **64-слотовый лимит очереди** — следствие партии планирования; покрывает
  сутки при интервале ≥20 мин; при 10-мин интервале очередь короче суток,
  пополняется на каждом открытии приложения.
- **Убийство приложения из recents** не отменяет запланированные уведомления
  (планируются через системный сервис).
- iOS: те же локальные уведомления работают, но MVP тестируем и
  выключаем только на Android.

## 7. Future: серверный word-of-the-day (опция, кандидат Phase 10)

MVP не требует изменений бэкенда. Если позже понадобится персонализация
слова под момент (слабые по SRS слова, анти-повторы между девайсами,
контекст дня) — серверный подбор:

- **course-service**: RPC `GetDailyWords(user_id, count)` — выборка из
  `courses.vocabulary` по уровню юзера с join на `srs.user_srs_items`
  (приоритет — слабые/never-seen), исключение недавно показанных
  (таблица-журнал `shown_words` или Redis-set с TTL).
- **gateway**: `GET /api/v1/vocabulary/daily?count=N`.
- Клиент дергает его при `reschedule()` как источник №1; локальный пул
  остаётся offline-fallback.

Плюс: персонализация и кросс-девайс дедуп. Минус: зависимость от сети на
момент планирования. Решение о реализации — по данным adoption MVP.

## 8. Out of scope

- Виджеты home/lock screen (недоступны сторонним на Android < 16).
- iOS-специфика (standby-режим, live activities).
- Rich-media уведомления (картинки, аудио) и TTS-озвучка слова из
  уведомления.
- Серверная часть — см. Future выше.

## 9. Метрики успеха

  использования фичи.
- Косвенная: доля дней с активной фичей у удержанных юзеров vs контроль
  (когда появится когортная аналитика).
