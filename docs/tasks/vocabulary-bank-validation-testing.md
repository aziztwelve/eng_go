# Банк слов: серверная проверка и сохранение попыток

Изменения подготовлены локально. Телефон, ADB, Metro и Android/Gradle для этих
проверок не нужны. Рабочий backend не запускается локально и не изменяется.

## Поведение

- Новый плеер отправляет `answer.validation_version=2`, UUID `attempt_id`, владельца `session_user_id` и
  фактический `value`. Владелец должен совпадать с авторизованным пользователем. `is_correct` и `score` для этого протокола сервер вычисляет
  сам для word_match, meaning_choice, fill_the_blank, sentence_builder.
- Регистр, пробелы и пунктуация нормализуются. Другие формулировки не считаются
  автоматически эквивалентными; для них нужны отдельные допустимые ответы.
- Прослушивание, раскрытие значения, произношение и свободные ответы имеют
  `assessment_mode=practice`, `score=0`, `is_correct=false`, `can_advance=true`.
  Это подтверждение выполнения, а не оценка знания или грамматики.
- Ошибка не продвигает шаг. Новый протокол не позволяет пропустить шаги.
- Попытка сначала сохраняется в AsyncStorage с ключом аккаунта. Владелец берётся из текущего JWT, включая гостевые сессии. Переход вперёд
  происходит после ответа сервера. При потере сети плеер ждёт на текущем шаге,
  повторяет отправку при восстановлении связи, foreground и по кнопке.
  Полное прохождение урока без интернета в эту реализацию не входит.
- Повтор с тем же attempt_id не создаёт попытку, прогресс и награду повторно.
  Повторное использование ID с другим ответом отклоняется.
- Первое прохождение и усвоение разделены: текст финиша направляет к повторению;
  существующий SRS-хук вызывается при первом завершении с консервативной quality=3,
  а не с максимальной 5. Это не новая модель оценки усвоения.
- Ошибка SRS/XP остаётся non-fatal. Надёжная доставка этих межсервисных событий
  через outbox — отдельная задача; эта доработка не гарантирует её.

## Автоматическая проверка без телефона

Из `microservices-course/elearning`:

```bash
./scripts/test-vocabulary-bank.sh
```

Нужны Go и локальные бинарники PostgreSQL (по умолчанию `/usr/lib/postgresql/12/bin`,
переопределяются `PG_BINDIR`). Скрипт создаёт временную БД с Unix-сокетом, применяет
миграции 33, 34, 36 в отдельной тестовой схеме, проверяет сценарии и останавливает
БД при выходе. Никакие сервисы приложения не запускаются.

Проверяется: неверная первая попытка, запрет пропуска, повтор ранее пройденного
шага, восемь параллельных одинаковых отправок, конфликт содержимого при повторе
ID и единственное событие завершения при параллельных финальных попытках.
Юнит-тесты дополнительно проверяют поддельный клиентский score и отсутствие
оценки правильности для практики.

Из `eng_mob`:

```bash
node scripts/test-vocabulary-queue.cjs
./node_modules/.bin/tsc --noEmit
./node_modules/.bin/eslint 'src/app/(tabs)/practice/vocabulary/[externalId]/learn.tsx' src/lib/vocabulary-attempt-queue.ts src/lib/vocabulary-attempt-queue-core.ts
```

Очередь проверяется на перезапуск после потери связи, параллельное добавление
и отправку, повторный ID, смену аккаунта и ошибку записи на устройство.
Это проверка логики и типов, не визуальный E2E интерфейса.

## Проверка контента перед публикацией

Из `services/course-service` (абсолютный путь к JSON заменить своим):

```bash
go run ./cmd/import-vocabulary-bank --dry-run --require-mobile-ready --file '/absolute/path/batch.json'
```

Dry-run не читает конфигурацию БД и не подключается к PostgreSQL. Дополнительный
флаг проверяет известные мобильному плееру типы и порядок 15 шагов, ключи ответов,
варианты, текст пропуска, токены предложения и наличие вопросов/образцов.
Это технический контроль готовности; редактор отдельно утверждает значения,
переводы, формулировки и качество материала. Новый inventory без полных карточек
не проходит этот контроль. Автоматическая генерация контента не выполняется.

## Совместимость и последующий выпуск

По development-workflow.md новые поля ответа аддитивные. Старые APK без
`validation_version=2` продолжают прежний путь проверки (assessment_mode=legacy).
Поэтому отказ от доверия клиентской оценке пока относится к новому протоколу;
compat-ветка удаляется после перехода всех поддерживаемых клиентов.

Перед выпуском: применить миграцию 000036, обновить backend с новым proto и
проверить API, затем выпускать новый плеер. Не запускать новый плеер против
старого backend: он сохранит попытку и будет ждать поддержку проверки.
Деплой, миграция рабочей БД и проверка телефона в этой задаче не выполняются
по прямому указанию пользователя «только разрабатывай».

## Результат локальной проверки

- Тестовый скрипт backend: service, PostgreSQL integration, gRPC API и gateway — прошёл.
- Четыре проверки очереди — прошли; полный mobile typecheck — прошёл.
- ESLint затронутой логики — без ошибок; общие предупреждения Array<T> в types/api.ts существовали ранее.
- Реальный A1 batch 001: 500 карточек, dry-run + require-mobile-ready — прошёл.
- Во время проверки обнаружено отсутствие необязательного grammar_targets в A1:
  импортёр теперь принимает отсутствие поля, сохраняя проверку переданного значения.
- Визуальный E2E, деплой и проверка на телефоне не выполнялись.
