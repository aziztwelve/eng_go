# Track Package Structure Standard

Этот документ фиксирует стандарт для **новых пакетов треков** (например
`A1_BUSINESS_ENGLISH_TRACKS_01_10_V2`) — как должна выглядеть папка с
файлами, сколько шагов на урок и какой набор полей допустим. Формат самого
JSON-файла трека (`lingoiq.track.v2`) описан в
[`11-track-import-contract.md`](./11-track-import-contract.md) — этот
документ его не заменяет, а дополняет конкретными правилами по количеству
шагов и структуре пакета.

## 1. Структура папки пакета

Пакет треков — это директория `tracks/{PACKAGE_NAME}_V2/` (вне этого
репозитория, в `eng/tracks/`), содержащая один JSON-файл на трек:

```
tracks/{PACKAGE_NAME}_V2/
├── {CODE}_T01.json
├── {CODE}_T02.json
├── ...
└── {CODE}_T10.json
```

- Один файл = один трек = один `lingoiq.track.v2` документ (см. контракт
  `11-track-import-contract.md`).
- Имя файла совпадает с `track.code` внутри него.
- Никаких вспомогательных файлов (`README.md`, шаблонов, метаданных пакета)
  внутри папки — вся нужная информация (`level`, `goal`, `track_type`)
  хранится в самом файле трека.
- Эталон структуры одного файла:
  [`TRACK_IMPORT_V2_MINIMAL_EXAMPLE.json`](../TRACK_IMPORT_V2_MINIMAL_EXAMPLE.json).

## 2. Количество шагов на урок

Каждый урок (`lessons[].steps`) должен содержать **от 13 до 15 шагов**.

- Допускаются повторяющиеся типы (например два `quiz`-шага в одном уроке) —
  строгого соответствия «один тип — один шаг» не требуется.
- Каждый урок должен покрывать разнообразие механик: минимум использовать
  большинство из 13 типов, перечисленных в таблице контракта
  (`11-track-import-contract.md`), а не концентрироваться на 2–3 типах.
- `order` внутри `steps` нумеруется последовательно `1..N` без пропусков,
  где `N` — итоговое количество шагов урока (13, 14 или 15).

### Почему 13–15, а не фиксированное число

Реальная выработанная практика (см. `A1_GREETINGS` в
`TRACK_IMPORT_V2_MINIMAL_EXAMPLE.json`) показывает, что полный охват всех
13 базовых типов шагов даёт естественный минимум 13 шагов на урок. Диапазон
до 15 оставляет свободу добавить усиленную практику (например второй
`quiz` или дополнительный `tap_words`) без искусственного растягивания
через дубли ради дубля.

### Правило для `match_pairs`: ровно один шаг на весь трек

В отличие от остальных типов, `match_pairs` не повторяется по урокам.
На **весь трек** должен быть ровно **один** шаг типа `match_pairs`, и в
нём — ровно **7 пар слов** (`data.pairs`, длина массива = 7). Он размещается
в первом уроке трека (`order: 1` внутри `lessons`).

Если при доведении урока до 13–15 шагов какому-то уроку не хватает типов и
среди недостающих оказался `match_pairs` — **не добавлять** второй
`match_pairs`-шаг. Вместо этого использовать дубль другого типа (например
второй `quiz` на основе других model-фраз урока), чтобы не нарушить правило
«один `match_pairs` на трек».

## 3. Обязательные поля трека (`track`)

Только эти 7 полей допускаются в объекте `track` (валидируется по
`TRACK_IMPORT_V2.schema.json`, `additionalProperties: false`):

| Поле | Обязательно | Назначение |
|---|---|---|
| `code` | да | Уникальный код трека, определяет стабильный id (`uuid5`) |
| `title` | да | `{en, ru}` — заголовок трека, видимый пользователю |
| `description` | да | `{en, ru}` — описание трека |
| `target_language` | да | Изучаемый язык |
| `native_language` | да | Родной язык — определяет, какая локализация показывается |
| `level` | да | CEFR-уровень (`A1`–`C2`) — используется для фильтрации каталога |
| `goal` | да | Записывается в `learning_tracks.motivation`; **должно совпадать** с одним из значений onboarding-целей мобильного приложения (`work, exam, travel, speaking, study, social, content, listening_shadowing`), не с произвольным свободным текстом — иначе трек не попадёт ни в одну цель каталога на моб |
| `track_type` | да | `thematic \| daily \| stories \| podcast` — определяет раздел/иконку в моб |

**Запрещённые поля** (были в старых пакетах, удалены как неиспользуемые):
- `tags` — не читается никаким кодом (ни импортёром, ни backend, ни моб).
- `icon_url` — не читается текущим импортёром; если понадобится в будущем,
  добавлять только вместе с реальной реализацией в
  `import_tracks_from_json.py` и коде отображения.

## 4. Обязательные поля урока (`lesson`) и шага (`step`)

Не меняются относительно `11-track-import-contract.md`:
- `lesson`: `code, order, title, objective, estimated_seconds, steps`.
- `step`: `id, order, type, title, instructions, estimated_seconds, data`
  — состав `data` зависит от `type` (см. таблицу в контракте).

## 5. Проверка перед импортом

Перед импортом нового пакета обязательно:

1. Валидировать каждый файл по `TRACK_IMPORT_V2.schema.json` (например
   через `jsonschema` в Python — `Draft202012Validator`).
2. Проверить, что каждый урок содержит 13–15 шагов:
   ```python
   for lesson in track["lessons"]:
       assert 13 <= len(lesson["steps"]) <= 15
   ```
3. Проверить, что во всём треке ровно один `match_pairs`-шаг и в нём ровно
   7 пар:
   ```python
   match_steps = [s for l in track["lessons"] for s in l["steps"]
                  if s["type"] == "match_pairs"]
   assert len(match_steps) == 1
   assert len(match_steps[0]["data"]["pairs"]) == 7
   ```
4. Проверить, что `track.goal` — одно из известных значений onboarding-целей
   (см. таблицу выше), иначе трек не появится в каталоге целей на моб.
5. Прогнать `scripts/import_tracks_from_json.py` для каждого файла и
   просмотреть сгенерированный SQL перед применением к БД.

(`A1_GREETINGS`). Пример полного пакета из 10 треков, приведённого к этому
стандарту — `A1_BUSINESS_ENGLISH_TRACKS_01_10_V2` (не в этом репозитории,
см. `eng/tracks/`).
